## New since yesterday
- **9640-latencyloom — "the loom"** (cycle 1086 WIDE winner). The lab's **first multi-user piece, ever** — you flagged multi-user + spatial as the lanes for this fire, and the jury named "zero multi-user in 15 cycles" as the one big gap. Several browser tabs (or people) weave one piece; each note reaches the others *late*, and that **latency is the instrument** — a delay slider (0–1200 ms) re-tunes the whole thing into a tighter or looser canon. No server: tabs sync peer-to-peer via `BroadcastChannel`, each client re-synthesizes locally, all locked to one shared metronome grid.
  - *Why it breaks the monoculture:* multi-tab input (not your piano), a clinical ink **network diagram** (not a particle field), **7-limit just-intonation** (not pentatonic), high-key paper (not amber/indigo) — off **every** tag the jury banned.
  - *The idea, from research:* latency-as-instrument (NIME 2025) + transmit-events-synthesize-locally (Cornelljam) + one shared metronome (GloMe). Chained same-day from the §1086 dive.
  - *Honest limit:* BroadcastChannel is same-machine only, so genuine **different-device** sync is the cycle-2 WebRTC deepening — cross-tab on one machine is real and works today.
